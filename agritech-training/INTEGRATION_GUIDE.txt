================================================================================
       AGRITECH TRAINING MODULE - INTEGRATION GUIDE
       Integration into an existing Symfony project with User sessions
================================================================================

This guide explains EVERYTHING you need to do to integrate the Training + Quiz
+ Certificate module into your existing Symfony project that already has a
User entity and session/authentication system.

Your existing User table:
  - id_u, nom_u, prenom_u, email_u, mot_de_passe_u, role_u, image_u,
    photo_face, date_creation_u


================================================================================
SECTION 1 : SQL - CREATE THE user_progress TABLE
================================================================================

Run this SQL in your existing database (the same database as your User table):

CREATE TABLE IF NOT EXISTS user_progress (
    id BIGINT AUTO_INCREMENT NOT NULL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    current_lesson INT DEFAULT 1,
    passed TINYINT(1) DEFAULT NULL,
    certificate_number VARCHAR(50) DEFAULT NULL,
    certificate_path VARCHAR(500) DEFAULT NULL,
    certificate_generated_at DATETIME DEFAULT NULL COMMENT '(DC2Type:datetime_immutable)',
    completed_at DATETIME DEFAULT NULL COMMENT '(DC2Type:datetime_immutable)',
    created_at DATETIME NOT NULL COMMENT '(DC2Type:datetime_immutable)',
    updated_at DATETIME NOT NULL COMMENT '(DC2Type:datetime_immutable)',
    completed_lessons JSON DEFAULT NULL,
    quiz_score INT DEFAULT NULL,
    UNIQUE KEY UNIQ_certificate_number (certificate_number),
    INDEX idx_user_id (user_id),
    INDEX idx_passed (passed),
    CONSTRAINT fk_user_progress_user FOREIGN KEY (user_id) REFERENCES user(id_u)
        ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

NOTE: Change "user" in the FOREIGN KEY line to match your actual user table
name (it might be "user", "users", "utilisateur", etc.).

SECTION 4 : CODE MODIFICATIONS (CRITICAL)
================================================================================

After copying the files, you MUST make these changes to connect the module
to your user session system.

--- 4.1 REPLACE HARDCODED userId = 1 ---

In the current code, the user ID is hardcoded as 1 in multiple places.
You need to replace it with the actual logged-in user's ID from your session.

FILE: src/Controller/QuizController.php
  Line 30:  CHANGE   $userId = 1; // Replace with session/auth user
            TO       $userId = $this->getUser()->getIdU();
                     (or use your session: $request->getSession()->get('user_id'))

  Line 46:  CHANGE   $userId = 1; // Replace with session/auth user
            TO       $userId = $this->getUser()->getIdU();

  Line 71:  CHANGE   $userId = (int)($data['userId'] ?? 1);
            TO       $userId = $this->getUser()->getIdU();


FILE: src/Controller/LessonController.php
  Line 30:  CHANGE   $userId = 1; // Replace with session/auth user
            TO       $userId = $this->getUser()->getIdU();

  Line 54:  CHANGE   $userId = 1; // Replace with session/auth user
            TO       $userId = $this->getUser()->getIdU();


NOTE: The method to get the user ID depends on YOUR authentication system:
  - If using Symfony Security:  $this->getUser()->getIdU()
  - If using PHP sessions:      $request->getSession()->get('user_id')
  - If using a custom system:   adapt accordingly

--- 4.2 REPLACE THE CERTIFICATE NAME (from prompt to user data) ---

FILE: templates/quiz/quiz.html.twig
  Line 267: CHANGE   let userName = prompt("Please enter your full name...") || 'Student';
            TO       let userName = '{{ app.user.nomU }} {{ app.user.prenomU }}';
                     (or pass the name from the controller as a Twig variable)

FILE: src/Controller/QuizController.php
  Line 73:  CHANGE   $userName = $data['userName'] ?? 'Employee';
            TO       Get the name from the session/user entity instead:
                     $user = $this->getUser();
                     $userName = $user->getNomU() . ' ' . $user->getPrenomU();

--- 4.3 FIX DOWNLOAD LINK IN QUIZ RESULT ---

FILE: templates/quiz/quiz.html.twig
  Line 320: CHANGE   actionsHtml += `<a href="/certificate/1/download" ...`
            TO       actionsHtml += `<a href="/certificate/${userId}/download" ...`
            (where userId comes from your session, pass it as a Twig variable)

        'questions' => $questions,

    })

SECTION 6 : ROUTE SUMMARY
================================================================================

These routes will be added to your project (auto-discovered via attributes):

  GET  /                         -> Home page
  GET  /dashboard                -> Training dashboard
  GET  /lesson/{number}          -> View lesson (1-9)
  POST /lesson/complete/{number} -> Mark lesson complete (AJAX)
  GET  /quiz                     -> Quiz landing page
  GET  /quiz/start               -> Start the quiz
  POST /quiz/submit              -> Submit quiz answers (AJAX)
  GET  /quiz/api/questions       -> Get quiz questions (AJAX)
  POST /certificate/{userId}/generate   -> Generate certificate
  GET  /certificate/{userId}/download   -> Download PDF certificate
  GET  /certificate/verify/{certNumber} -> Verify certificate (public)
  GET  /certificate/{userId}/status     -> Certificate status (AJAX)

WARNING: Make sure none of these routes conflict with your existing routes.
If they do, change the #[Route('/...')] prefix in the controllers.
For example, you could change #[Route('/quiz')] to #[Route('/training/quiz')].

================================================================================
SECTION 10 : HOW THE FLOW WORKS AFTER INTEGRATION
================================================================================

1. Employee logs in to YOUR project (session stores user_id = id_u)
2. Employee visits /dashboard -> sees 9 lessons
3. Employee clicks each lesson -> completes lesson_1 through lesson_9
4. After all 9 lessons, the "Take Exam" button becomes active
5. Employee takes the quiz (30 questions, 30 min timer)
6. Quiz is submitted -> score calculated server-side
7. If score >= 70%:
   - passed = true saved in user_progress
   - Certificate PDF generated via dompdf
   - Saved to public/certificates/CERT-XXXXXXXX.pdf
   - Employee downloads the PDF
8. If employee tries to access /quiz/start again:
   - They see "You Already Passed" page (blocked from retaking)
9. Certificate can be verified publicly via /certificate/verify/{certNumber}
